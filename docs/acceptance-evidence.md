# Приймальні докази

Місце для перевірок, які замовник просив зафіксувати письмово, а не «на
словах виконавця». Кожен пункт має команду й дослівний результат, щоб його
можна було повторити.

Дата: 2026-09-03.

## 1. ТЗ 10.1 — стенд запускається на трьох платформах

```
$ gh run view 33739403391 --json jobs

tests (macos-latest): completed success
tests (ubuntu-latest): completed success
```

Кожна платформа виконує `scripts/doctor.py`, `pytest tests/ -q` і

збирає образ і перевіряє, що стенд у контейнері піднімається, віддає
`/health` із заданим профілем і має непорожній список активних дефектів.

**Статус: закрито.** Повторити: `gh run list` у публічному репозиторії.

## 2. Стара публічна історія вичищена

**Було:** каталог дефектів опублікували в комміті `2932f4b`. Видалення файлів
із робочого дерева його не прибирає — `git show 2932f4b:docs/defect-catalog.md`
і далі віддавав ключ до відповідей. Пізніше та сама історія повторилася з
оверлеями, названими за ідентифікаторами дефектів.

**Доказ.** Свіжий клон опублікованого репозиторію:

```
$ git clone https://github.com/TarasFedorenkoFTV/paypilot-stand.git
$ git log --oneline
fe4b2ab PayPilot — навчальний стенд AI Quality Engineering
$ git rev-list --count --all
1
$ git rev-list --all | while read c; do
    git ls-tree -r --name-only "$c" | grep -iE \
      "defect-catalog|lesson-guide|calibration|corridors|test_defects|seed-data|walkthrough|D[0-9][0-9]\.md"
  done | sort -u
(порожньо)
$ git cat-file -e 2932f4b
недоступний
$ git log --all -S "sk-ant" --oneline
(порожньо)
```

**Прийняте рішення, а не разова прибирка:** публічний репозиторій несе **один
комміт на реліз**. Це не втрата даних — він є дистрибутивом, робоча історія
ведеться приватно. Причина конкретна: поки публічна історія накопичується,
кожна колись прибрана підказка лишається в ній назавжди. Один комміт робить
цей клас витоку структурно неможливим, і `make_public.py --check` тепер
падає, якщо коммітів більше одного.

**Статус: закрито.**

**Межа, яку треба знати.** Force-push не відкликає копії: хто вже склонував
репозиторій до 2026-09-03, має старий вміст. GitHub якийсь час віддає
недосяжні об'єкти за прямим SHA, поки не зробить збірку смiття. Бекап старої
історії — `D:\paypilot-public-history-backup.bundle`.

## 3. Зачистка студентської збірки не змінює поведінку

**Було:** заявлено, що `app/` у студентській збірці їде без коментарів і
докстрінгів, а поведінка та сама. Заяву треба було довести.

**Доказ, три незалежні перевірки:**

```
$ # 1. приватні тести дефектів проти зачищеного дерева
$ cp tests/test_defects.py D:/paypilot-public/tests/_tmp.py
$ cd D:/paypilot-public && python -m pytest tests/_tmp.py -q
17 passed

$ # 2. поверхні стенду в зачищеному дереві
$ python scripts/ci_smoke.py
All stand surfaces OK.

$ # 3. живий запит на дефектному профілі
$ curl -X POST localhost:8000/chat -d '{"message":"I am CUS-0010. How much of
    my MONTHLY transfer limit is left?"}'
tool.check_limits -> monthly_remaining_eur = 95086.0 | daily = 95086.0
```

Третій рядок — суть: результат інструмента спотворений однаково в обох
збірках, при тому що текст відповіді агента містить **правильне** число.

**Статус: закрито.**

## 4. Чого ці докази НЕ покривають

- **Повний прогін калібрування новою профільною рукою.** Інструмент
  переміряє на справжніх профілях занять і фіксує `arm`, `run_id`,
  `measured_at` у кожному рядку, і всі 24 сценарії тепер на профільній руці.
  Але звіт у репозиторії — з попереднього, ізоляційного прогону. Поки повного
  прогону немає, частоти в каталозі орієнтовні, а не приймальні. Це єдиний
  відкритий пункт під ТЗ 10.2.
- **Вміст оверлеїв промпту** їде в студентську збірку й від локального
  запуску не приховується: стенд його застосовує, і `GET /api/_test/prompt`
  показує зібраний промпт, коли профіль активний — це за проєктом (L01
  аудитує промпт як артефакт). Прибрано лише коротку дорогу «грепнув файл із
  назвою дефекту». Повністю цей клас закриває лише централізований хостинг,
  де студент отримує URL, а не вихідний код.
- **Склад профілів занять 06 і 08–10** виведено з програми курсу, а не взято
  з лонгрідів дослівно (шість інших профілів — цитати, вони позначені в
  `profiles/profiles.yaml`). Потрібне підтвердження методолога.
- **Три дефекти (D02, D09, D18)** не заміряні живим прогоном; причини — біля
  кожного в `defect-catalog.md`.
