# Еталонний зібраний контур (L12)

П'ять компонентів під однією командою. Вхід і вихід кожного розведені — це і
є те, що фіксують ADR нижче.

```
sets/*.jsonl ──► loader.py ──► runner.py ──► assertions.py ──► Verdict
   (дані)        (валідація)   (виконання)     (рішення)          │
                                   │                              ▼
                    stand.py ◄─────┤                        reports/*.json
              (чат, трейс, стан)   │                     (6 полів версії)
                                   ▼
                  generate_from_engines.py ──► engines (оракул)
```

## Команда

```bash
cd ../evals && SET=l03_reference GATE=daily python runner.py
```

Код повернення: `0` — усе зелене, `1` — є падіння. Це і є інтеграція з гейтом.

## П'ять компонентів

| Компонент | Вхід | Вихід |
|---|---|---|
| `loader.py` | шлях до `.jsonl` | список валідованих кейсів + `set_hash` |
| `runner.py` | набір, профіль стенду | запис прогону з 6 полями версії |
| `assertions.py` | дані: текст, трейс, рядки БД | `Verdict(passed, level, detail)` |
| `stand.py` | HTTP до стенду | відповіді, трейси, стан, керування |
| `generate_from_engines.py` | виклики рушіїв | кейси з `expected_number` і `engine_call` |

## Шість полів версії в кожному записі

`prompt_version` · `set_hash` · `profile` · `judge_model` · `rubric_version` ·
`elapsed`

Два прогони порівнюються **лише** коли `set_hash` збігається. Дописаний кейс
змінює хеш — це не незручність, це властивість.

## ADR

- [ADR-001 — dataset ↔ runner](adr/ADR-001-dataset-runner.md): набір несе
  лише дані, жодного виконуваного коду
- [ADR-002 — runner ↔ assertions](adr/ADR-002-runner-assertions.md):
  assertion отримує дані, не з'єднання
- [ADR-003 — assertions ↔ движки](adr/ADR-003-assertions-engines.md):
  очікування дає виклик рушія на етапі побудови набору

Кожен ADR має три обов'язкові рядки: **що обміняли**, **чого не робимо**,
**за яких умов переглянемо**.

## Декларація використання AI

Контур і ADR писані з асистентом. Що відхилено з його виводу:

1. **Дозволити лямбди в наборі** — саме те, що забороняє ADR-001. Виглядало
   гнучко, зробило б `set_hash` брехливим.
2. **Дати assertions клієнт стенду**, «щоб не тягати дані» — заборонено
   ADR-002: вартість прогону перестала б бути передбачуваною.
3. **Викликати рушій усередині assertion** — заборонено ADR-003: дефект у
   самому рушії став би невидимим, бо обидві сторони порівняння зсунулися б
   разом.

Показово, що всі три пропозиції асистента — це рівно ті три межі, які ADR
проводять. Межу видно тільки тоді, коли її хтось намагається перетнути.
